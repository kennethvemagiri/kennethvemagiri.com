Offline evaluation for RAG: metrics I actually track

BLEU won’t tell you if the model cited the wrong paragraph. I combine retrieval diagnostics with lightweight answer checks before any template or embedding change ships.

Kenneth Vemagiri · ~8 min read · April 2026

  • RAG
  • Evaluation
  • ML ops

1. Build a golden set per tenant or domain

Twenty to fifty question–answer pairs labelled by someone who knows the source docs beats five hundred synthetic QA pairs. I store question, gold_chunk_ids (or page ranges), and gold_short_answer where possible.

2. Context precision and recall

For each question I log which chunks entered the prompt. Recall@k: did any of the top‑k include a gold chunk? Precision@k: what fraction of top‑k are relevant? Purging noisy chunks often improves end-to-end accuracy more than prompt tweaks.

3. Answer groundedness

I use a simple rubric: every sentence in the model answer must be entailed by the retrieved context or marked as “general knowledge”. Entailment can be a smaller cross-encoder or an LLM-as-judge with fixed temperature—consistency matters more than the specific model.

4. Abstention and refusal quality

For questions with no supporting passage, the correct output is often “I don’t have that in the documents.” I track false-answer rate on those items separately; it is where hallucinations hurt trust most.

5. Regression CI

Every change to chunk size, embedding model, or reranker runs the same JSON suite; I fail the PR if precision@8 drops more than an agreed epsilon. Production logs feed new failures back into the golden set.
