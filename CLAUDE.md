## Architecture Overview

This is a **dual-architecture portfolio site** with two distinct codebases under one repo:

1. **Main site** (`/`) — Static HTML/CSS/vanilla JS single-page portfolio (hero, about, projects, contact). No build step required for development; assets are hand-written and minified for production.

2. **MWF sub-app** (`/featured-projects/MWF/`) — A full React 18 SPA (MedWorkFlow) built with Vite, Tailwind CSS, React Router v7, Framer Motion, Lucide React, Three.js, and React Hook Form. Served at `/featured-projects/MWF/` (set as Vite base path).

Other featured projects (`GoCafeCo`, `InPlan`, `Pronto`, `WiseWeb`) are standalone static HTML showcase pages with no build process.

## Commands

### Main Site
```bash
# Convert PNG assets to WebP (run after adding new images)
npm run build

# Minify CSS and JS for production
npm run minify

# Regenerate awards strip data from /awards/ directory
node build-awards.js
```

### MWF React App
```bash
cd featured-projects/MWF

npm install        # Install dependencies
npm run dev        # Dev server at http://localhost:5173 (auto-opens)
npm run build      # Production build to /dist/
npm run preview    # Preview production build
```

## Key Architecture Notes

- **Stylesheets and scripts**: Public HTML loads source `styles.css` and `script.js`. After editing those files, run `npm run minify` only if you intentionally switch markup to `styles.min.css` / `script.min.js`.
- **Awards strip**: `/awards/awards-data.js` is auto-generated by `build-awards.js`. Do not hand-edit it.
- **Contact form**: Uses Formspree (action URL embedded in `index.html`). No backend needed.
- **Caching**: `_headers` configures Netlify to cache CSS/JS/images for 1 year (`immutable`). HTML always revalidates. This is why minified filenames matter — cache busting requires filename changes.
- **MWF routing**: React Router v7 with a `<Layout>` wrapper for most routes. The `/skills` route is standalone (no layout). Layout lives at `src/components/layout/`.

### Homepage Work grid (`data/site-content.json` + Hire flow)

- **Rendering**: [`js/render-site-content.js`](js/render-site-content.js) fetches [`data/site-content.json`](data/site-content.json) and fills `#projects-grid-root` (and related hire/more-apps mounts).
- **Default `#work` view**: Featured projects first, then others; **top three tiles** plus the static “More incoming” pipeline tile (same as before hire matching).
- **Hire → Work**: [`hire.html`](hire.html) saves the search box text as **`sessionStorage.hireSearchQuery`**, then sends users to `index.html#work`. On load, `render-site-content.js` reads that key once: scores **every** project with lightweight keyword overlap (title, tagline, metric, `stack`, and optional **`searchKeywords`**), sorts **all** projects by score, renders **every** tile, shows **`#hire-match-banner`** above the grid, then **clears** `hireSearchQuery` so refresh restores the default three-tile view.
- **`searchKeywords`** (optional per project): string array of recruiter-facing synonyms (tools, roles, phrases). Higher scoring weight than body fields; extend [`QUERY_ALIAS`](js/render-site-content.js) for common aliases (`gpt` → `llm`, etc.).
- **`currentBuild`** (optional, at most one project): When `true`, that project’s `title`, `tagline` (or `metric`), and GitHub action drive the **Developer View** “Current project” card in [`productive_version/script.js`](productive_version/script.js). If unset, the card falls back to the first **featured** project that has a GitHub link in `actions`.

## Deployment

Hosted on **Netlify** with automatic deploys on push to `main`. No GitHub Actions.

- **`netlify.toml`**: `npm run build`, publish `.`, functions in `netlify/functions/`, rewrite `/api/github-contributions` → function.
- **`_headers`**: HTTP cache headers for static assets.
- **GitHub contributions API**: `netlify/functions/github-contributions.js`; env vars `GITHUB_TOKEN`, optional `GITHUB_LOGIN` — see `NETLIFY-GITHUB.md`.
- **Local with functions**: `npm run dev:netlify` (`netlify dev`); static-only: `npm run dev`.
