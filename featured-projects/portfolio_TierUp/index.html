How the Search Works

The core flow streams results to your browser in real time — you see cards appearing as they arrive, not after a loading spinner.

01

User submits search → FastAPI opens an SSE stream. The browser is now listening.

02

Apify actor launches → LinkedIn search URL gets built from your filters. The scraper polls every 2 seconds, max 35s timeout.

03

Raw cards stream in → Each job appears in the UI immediately — title, company, location. No scores yet, but you're already scanning.

04

GPT-4o scores in parallel → Your profile + all listings → one prompt. Scores, fit analysis, gap warnings, and ATS tips come back.

05

Visa check runs → Each company name gets normalised and matched against 50,000+ entries in the Home Office register.

06

Cards update live → Score pills, visa badges, and analysis text appear on each card. Done.

Without Apify, the system falls back to GPT-4o's tool-calling capability — DuckDuckGo search + page fetch, all orchestrated as an agentic loop.

Architecture

Full-stack, async-first, single-file database. No over-engineering — the "Troy" approach.

Backend
FastAPI — async endpoints, SSE streaming via generators. Python 3.12+, aiosqlite, uvicorn.
AI Layer
GPT-4o — job analysis, CV generation, and agentic web search with tool-calling. OpenAI SDK, function definitions for web_search + web_fetch.
Scraping
Apify Cloud — LinkedIn jobs actor with start-poll-abort pattern. Fallback: DuckDuckGo via ddgs + requests.
Frontend
Next.js 14 — file-based routing, TypeScript, Tailwind CSS. SSE consumption via ReadableStream.
Database
SQLite — single-file, zero config. Applications, sponsors, profiles, search history. Async via aiosqlite.
API Design
14 endpoints — RESTful for CRUD, SSE for streaming. Next.js rewrites proxy /api/* to FastAPI.

The Visa Matching Engine

The Home Office publishes a CSV of 50,000+ licensed sponsors. TierUp imports it into SQLite, normalises every company name (lowercase, punctuation stripped), and runs a two-pass match:

# 1. Exact normalised match
SELECT * FROM sponsors
WHERE name_norm = normalize('Google')

# 2. Fuzzy fallback — catches "Google UK Ltd"
SELECT * FROM sponsors
WHERE name_norm LIKE '%google%'

Result: every job card gets a green ✓ Visa Sponsor badge or a red warning — automatically. No manual checking.

Design Decisions Worth Noting

  • SSE over WebSockets — one-directional stream is all job search needs. WebSockets would be over-engineering for a unidirectional data flow. Simpler, fewer failure modes.
  • SQLite over Postgres — this is a personal tool. Single-file database means zero infrastructure, instant setup, and the entire state fits in one autojob.db file you can back up with copy-paste.
  • Apify over custom scraping — LinkedIn blocks scrapers aggressively. Apify handles proxy rotation, browser fingerprinting, and CAPTCHA solving. I focused on the AI layer, not on fighting anti-bot systems.
  • GPT-4o as an agent, not just a scorer — the web search fallback uses tool-calling to run DuckDuckGo searches and fetch pages in an agentic loop. The AI decides what to search, when to fetch a page, and when it has enough data to score.
  • Normalised sponsor matching — exact matching fails when LinkedIn says "Google" but the register says "Google UK Limited." Normalisation + fuzzy LIKE catches these edge cases without needing a vector database.
Every decision was driven by the same principle: what gets a working product to my hands fastest?

What I Learned Building This

SSE Streaming Is Underrated

Most devs reach for WebSockets by default. But for server-to-client data flow — which is exactly what AI streaming responses are — Server-Sent Events are simpler, auto-reconnect out of the box, and work through proxies without extra config. The FastAPI generator pattern makes it clean:

async def search_generator():
    yield sse_event("status", {"message": "Scraping LinkedIn..."})
    jobs = await scrape_linkedin(params)
    for job in jobs:
        yield sse_event("job", job)  # card appears immediately
    scores = await score_with_gpt4o(jobs, profile)
    yield sse_event("jobs", scores)  # cards update with AI analysis

AI Tool-Calling Changes Everything

The web search fallback isn't a hardcoded scraper — it's GPT-4o deciding what to search, evaluating results, fetching pages, and reasoning about which jobs match. The AI orchestrates its own tool calls. I just defined the tools and the goal.
